# 示例核对说明

先把 [虚构资料](demo-input.md) 交给 Agent，按 README 请求生成今日安排，再核对以下可观察结果。这里没有声称已经经过所有宿主或模型验收。

- 三个项目均应出现；盘点日为 2026-04-08，资料模式，未知审批节点保留待核对。
- 项目甲不能继续建议催交已经收到的第二版。应核对意见对应关系并准备反馈；收到稿不等于审核通过，准备反馈不等于已发送。
- 项目乙不能写已正式收件，也不能写已逾期或审批完成。查询凭证、预计反馈和实际反馈分开。
- 项目丙的今日动作是整理讨论对比稿并列费用缺口；不能编造金额、替负责人选择方案，或把次日讨论写成今天已召开。
- 可以按今日到期的甲、丙准备工作说明排序，给出动作、完成标准和来源；不输出没有基数的绩效数字。
- 请求明确只读时，不能写入示例、发消息或宣称生成内容已存档。

其他建议场景：同一项目出现冲突日期；只有历史报告没有当前证据；用户要求记录但未提供位置；已经存在同名技能时安装应停止。实际验收记录应说明使用的宿主、请求、资料、结果和局限。
