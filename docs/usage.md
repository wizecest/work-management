# 使用与保存约定

首次使用可直接提供几份 Markdown 或文本资料，不要求先搭建项目系统。长期使用再用 [工作空间模板](../skills/work-management/assets/workspace-template.md) 明确读取与保存位置。

## 常用请求

| 目的 | 请求 |
| --- | --- |
| 今日安排 | 根据指定资料整理今日安排，列出所有项目，保留来源，不改项目事实 |
| 记录事实 | 记一下，示例项目甲今天收到修改稿；追加到我指定的工作日志 |
| 仅检查漏同步 | 检查最近三天工作日志与现有事件是否有漏记，只列清单 |
| 周总结 | 整理本周工作，说明统计口径，保存到指定成果目录 |
| 管理层审视 | 看全部项目，说明干预是否有效，不改任何文件 |
| 对外台账 | 按进展、问题、措施、下一步整理台账，仅输出，不保存 |
| 复盘 | 根据时间线复盘本次延期，区分已知原因和推断，先给草稿 |

命令名称对应同样意图：`/work day summary`、`/week`、`/month`、`/work quarter summary`、`/year`、`/manager-review`、`/ledger`、`/work log`、`/work sync --days 3 --check-only`、`/work retrospect`、`/work extract`。它们只是技能内的路由约定，并非可直接在终端执行的命令。

## 什么会保存

查询、今日盘点和管理层审视默认只读；“记一下”要求记录明确事实。周/月/季/年总结与台账在已有明确成果目录时默认保存成果，用户的“仅输出”优先。没有明确位置时先提供正文，不猜路径。事实、日志和成果是不同写入目标；生成报告不会自动更新项目状态。

直接文件模式只做已授权追加或新增成果，不提供跨多个文件的原子事务保证。已有事务系统的项目必须使用其正式入口；不能把文件追加模式描述为已完成正式入账。

## 如何检查结果

先看范围与截至日期，再查每个结论的来源。确认计划没有变成完成、已完成事项没有重复列入待办、等待事项没有分给错误对象、对外台账没有内部评论。任何没有来源的数字都应回到原始资料重核。

技能静态校验通过仅说明文件结构等检查通过；真实 Agent 的结果仍应结合具体资料验收。
