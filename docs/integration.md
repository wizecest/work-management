# 系统适配约定

默认资料模式可独立使用技能说明，不需要原仓库。需要正式项目状态与事实入账时，接入已有系统，避免把技能改造成另一套状态内核。

| 所需能力 | 适配系统必须提供 | 缺少时如何处理 |
| --- | --- | --- |
| 项目范围 | 唯一项目标识、默认汇报范围和排除项 | 只按用户本次提供范围读取 |
| 当前状态 | 状态及截至时间、证据、新鲜度或冲突提示 | 标状态待核对，不从旧日志猜节点 |
| 事项 | 事实、问题、措施、下一步、核验条件及已有 ID | 仅整理有依据的内容，不编造身份 |
| 事实记录 | 正式事务入口、授权检查、失败处理和可回读凭证 | 只给记录稿，或按已约定资料模式记普通日志 |
| 报告保存 | 目标位置、版本保护、正文与来源的关联 | 新增成果或仅输出，不覆盖人工修改 |
| 通知 | 宿主实际送达记录、历史去重、用户授权 | 不建立自动通知，不宣称已送达 |

## PM-Obsidian 适配

原系统采用 `events + graph + rules → Runtime v2 → ProjectStatus`，组合级工作使用 `ProjectStatus.business_matters`。这些是原系统的接口约定，本发布包未包含其实现。

- 当前工作安排通过原系统 `control_plane_tool.py today` 等正式入口读取，不能把主页、旧导出或报告当作运行态。
- 事实记录通过 `capture-note` 或 `sync-from-worklog` 正式事务执行；具体参数、锁、回滚与提交凭证以目标系统当前合同为准，不从本说明复制实现。
- 成果保存使用原系统 `pm_report_workflows.py` 等受保护入口，不能手工覆盖原报告。
- 单项目项目体检与专业结论交给系统已有项目主控及对应专业技能，不因本包未包含它们就声称已经完成审查。

接入前在目标工作空间核实这些入口实际存在及其版本。原系统的 AGENTS、assistant-runtime、数据架构与业务合同负责规则；本包只组织工作管理输出。

## 主动简报

只有用户要求定期检查时才使用宿主现有调度；没有实质变化或无需行动时保持安静。候选扫描、人工或 Agent 核对、实际送达分别记录。通知历史由宿主管理，不新增第二套项目状态；手动查询不能因曾提醒过而隐藏事项。
