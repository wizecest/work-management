# 对外台账

默认汇总已确认活跃项目，本月截至当前可核实日期；用户指定项目或期间则按指定范围。没有活跃项目清单时只使用用户提供范围，说明覆盖限制。

先核对当前权威状态，再用原始记录核对时间线、成果和正式口径。历史台账可以用作结构参照，不能当成新的业务事实。用户给出现有台账时保留其字段和统计口径，不自行换表。

每个项目独立一块，包含：

- 项目名称。
- 项目进展情况（项目时间线）：只写有依据的正式工作节点，按“YYYY年M月D日，事项。”逐行呈现。日期不明使用有依据的月份并标待确认，不编造具体日。
- 存在问题：适合对外的实质制约、跨单位协调或待决事项，不放个人提醒、内部催办过程和系统字段。
- 解决措施：与问题逐项对应，区分已采取、拟采取和待补充，不能写成已经取得结果。
- 下一步工作计划：具体成果或正式推进动作，有日期依据时写日期；不能保证的日期标目标日期。
- 待确认／待补充：影响采用的事实缺口或冲突。

无已确认外部制约可写“暂无已确认的重大外部制约因素”，不把未知写成无问题。多项目用分隔线分开；内部复盘、风险猜测和 Agent 运行信息不进入可复制的台账正文。

已知成果目录时默认存档一份本次成果，不改写项目事实。用户要求仅输出则不保存；要求在线更新时必须另核对目标台账、字段及已有写入授权，不能因生成草稿就宣称在线台账已更新。
