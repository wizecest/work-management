# 今日安排

## 读取与排序

确定截至日期与项目范围，逐项目检查目标、已确认状态、截止日、未完成事项、等待对象和后续证据。全部在范围内的项目都应出现；不能只挑重点项目后把其余项目遗漏。

接入系统时使用权威事项和状态分类。资料模式只使用明确承诺和已确认事实；历史未完成记录先查后续材料，证据不足的单列核对，不直接判定逾期或失败。未来承诺不能写成截至日之前的成果。

排序考虑：有依据且可执行的今日截止或逾期事项；影响执行的真实协调与决策；已到约定反馈日的等待事项；其他风险和准备工作。前置条件未知的动作不列成可以直接报送或关闭节点。内部交接与外部等待分开。

## 输出：六段正文及附录

1. **今日判断**：最值得做什么，依据是什么。区分判断不了和已核实正常。
2. **重点项目异常**：项目、目标日期、卡点、影响、已采取措施及其结果。没有重大异常时简短说明。
3. **今天需要你介入**：真实需要协调、决策或汇报的事项；说明要决定什么、最晚时间、已完成准备和不处理的影响。资料读取失败、内部映射缺口归入核对结果。
4. **今日重点执行**：每件写清项目、事项、对接人或待明确、具体步骤、完成物、目标日期、来源及当前依据。重点可先展示 3–5 件，其余不能丢弃。
5. **前次安排回收**：按最新证据说明已完成、推进中、已取消或未核实。没有记录不等于没做；无需在首次使用时虚构上一版。
6. **核对结果**：影响判断的资料缺口、证据冲突和待确认内容；列出还能先做什么。

附录按需要保留：全部项目各一行；已逾期、今日到期、未来七天清单；今天不承诺但已识别的事项及处理时间；来源位置和日期。正文优先呈现重点，所有待处理事项在正文或附录中均可找到。

## 把待办变成具体工作

重点事项不能只重复标题。补齐产生原因、当前已做到哪一步、今天要找谁拿什么、拿到后怎么看、需要准备的沟通文本、做到什么算完成。缺日期或负责人时直接标明，不代填。

例如“跟进评审回复”应具体到“核对已收稿与上一轮三条意见是否逐条对应，列出仍需说明的条目并准备反馈稿”。准备反馈稿不等于已反馈，收到回复不等于审核通过。

不因今日盘点自动同步日志、发送催办或建立定时监控。只生成草稿时如实说明。用户明确要求保存时写到已约定成果目录，回读后报告路径。
