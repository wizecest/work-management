# Work Management

把已知工作整理成具体动作和可核查成果。先核对用户指定的范围、资料截止日、现行状态源与保存位置；能从现有资料查清的先查，不让用户重复填写。

## 选择模式

| 用户请求 | 按需读取 |
| --- | --- |
| 今日安排、`/today`、空参数 `/work`、`/work day plan` | [daily.md](references/daily.md) |
| 当日、周、月、季度、年度总结，`/week`、`/month`、`/year` | [summaries.md](references/summaries.md) |
| 从管理层看全部项目、`/manager-review`、`/work portfolio review` | [portfolio.md](references/portfolio.md) |
| 项目进展、问题措施与下一步台账，`/ledger` | [ledger.md](references/ledger.md) |
| 记一下、日志、补同步、复盘、素材提炼 | [records.md](references/records.md) |

这些名称用于理解意图，不代表宿主已经安装同名命令。只加载命中场景的说明。没有需要处理的信息时简洁回答，不强套整份报告。

## 先确定资料模式

**默认资料模式**：使用用户提供的原始资料和带日期的明确陈述。区分历史经过、截至某日的已确认情况和当前仍待核实的情况。没有权威当前状态时标明“资料模式／状态待核对”，可以安排核对、起草和资料整理，不宣称流程就绪或审批完成。

**系统适配模式**：宿主已有权威状态服务时，按其合同读取当前状态和事项，再定向核对原始记录。系统读取失败不以旧报告替代；无关项目可继续处理。日志只补充事实和原因，不重新计算另一套当前节点。事实写入走该系统已有事务，按回执报告。

首次建立资料约定时可使用 [工作空间模板](assets/workspace-template.md)，已有清楚约定则直接复用。

## 事实、动作和结果

- 每个重要结论保留来源文件或记录位置及日期；统计必须说明范围、分母和去重口径。读取来源原文，不用旧总结代替。
- 同一事项沿用已有标识，没有标识则按项目、事项、版本或轮次核对，不随意新增业务身份。新版本、新会议或后续处理已覆盖的旧建议不能继续当作当前待办。
- “计划提交”不等于已提交，“已发出”不等于已收件，“收到修改稿”不等于审核通过，“做了沟通”不等于问题解决。动作是否完成与业务节点是否完成分别判断。
- 问题、已采取措施、拟采取措施、下一步和核验条件分开写。没有措施证据写“拟”或“待补充”。证据冲突只限制依赖它的结论，不把所有工作都暂停。
- 不编造项目、负责人、日期、金额、审批条件、成果版本或审查轮次。需要专业结论时调用当前可用专业能力；没有对应能力就说明具体判断缺口。

## 执行和保存

查询、盘点、审视和总结不自动取得修改项目事实的授权。用户说“记一下”属于记录请求，事实清楚且位置已知时直接记录，不重复确认。起草材料、保存成果、发给他人、关闭事项分别核对已有授权。

低风险且已授权的整理、起草和新增成果直接完成。记录变更后回读，说明实际写入位置；没有写入能力则交付可复制文本并说明尚未保存。已有文件不直接覆盖，先核对版本；没有受保护保存入口时新增一份成果。不得报告未执行的写入、发送或节点关闭。

当用户要求周/月/季/年总结或台账且已有明确成果目录时，默认存档生成成果；用户要求仅输出时不保存。今日安排和日总结按用户的保存约定执行。项目事实不因报告存档而改变。

具体项目的路径选择、专业审查和关键节点结论交由适用的项目主控或专业能力；本技能负责组合级排序、记录组织和汇报。宿主及用户当前约定优先，不要求安装不存在的配套技能。
